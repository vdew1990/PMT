# Project Management Tool

Cost control, claims, variations and risk for an EPC contract, built from the live Pronto-driven workbook. Start a project
from a template, load the proposal allowances, upload the Pronto exports, and the dashboard, cost control and reports follow.

Commercial in Confidence. All amounts are AUD excluding GST. Dates are DD/MM/YYYY in the interface and ISO in the database.

## Run it

```
./run.sh                 # Mac or Linux: creates .venv, installs requirements, serves http://127.0.0.1:8000
run.bat                  # Windows: double-click; does the same, and offers to install Python (current user, signature checked) if it is missing. PMT.exe runs it hidden behind a small window with a progress bar, the current step and "More info" for the details; source in launcher/
python -m demo.build_demo --seed --db data/demo.db   # optional: a fictional demonstration project
```

The first screen offers "Load the demonstration project". It is entirely fictional (invented people, suppliers, rates and amounts).
On one PC, data lives in `data/pmt.db` (SQLite). Set `PMT_DB` to use another database file. The Python environment and
compiled files are kept in `%LOCALAPPDATA%\PMT` (Windows), never in the program folder.

## Sharing a project through SharePoint

No server is needed. Everyone runs PMT on their own PC; changes travel through a folder that OneDrive syncs.

1. Put the PMT program folder (PMT.exe, run.bat, app, static, demo, requirements.txt) in a SharePoint document library,
   and create an empty folder called `shared` inside it, next to PMT.exe.
2. Each team member opens the library in the browser and chooses **Sync** (or **Add shortcut to My files**), then sets the
   PMT folder to **Always keep on this device**.
3. Each person double-clicks PMT.exe in their synced copy. The first run installs Python packages into `%LOCALAPPDATA%\PMT`.
   After that, clicking PMT.exe in SharePoint in the browser also works: the downloaded copy finds the synced folder and
   starts PMT from there (without a synced copy it explains how to sync).
4. If the team already used PMT on one PC, that person publishes the old database once from the welcome screen
   ("publish an existing database", usually `data\pmt.db` of the old copy) while the shared folder is still empty.

How it works: each copy keeps its own database in `%LOCALAPPDATA%\PMT\replicas` (an SQLite file must never sit in a
synced folder). Every change is written to a change log with the person who made it, and published to
`shared/journal/<person>@<PC>/<month>.jsonl`. Each copy reads the others' journals every 15 seconds and merges them
(latest change wins per field; deletes are final). The person is read from the OneDrive for Business sign-in on the PC
(their Microsoft 365 account), so nobody types a name. This is attribution among colleagues, not a security boundary:
access to the project is whoever can open the SharePoint folder.

**Who changed what.** CONTROL > Activity and history lists every change by person, with old and new values. Accruals show
who raised them and who changed them last; every record has a History button, and the cost-control drawer has a History
tab per line. Automatic changes say so, for example "Automatic: invoice landed in Pronto" when an accrual reverses.
Click your name at the top right to set your role (Project Manager, Project Coordinator...) and to see who else is
working on the project and when each copy last synced.

## Starting a new project from this one

Settings, "Templates and new projects": mark this project as a template, or use "+ New project" and choose a source. Structure,
allowances, resources, rate card and project schedule names can be copied. Pronto data, claims, accruals and history never are.
"Clear project data" wipes a live project back to a clean shell (identity and standard CBS stay).

## Design notes

* `app/engine.py` computes every line, then rolls up through the tree. Results are cached per database and project version.
* The CMT excludes accruals from its EAC. This tool includes them and shows the CMT-style figure on the Reconcile page.
* A closed PO commits only what was received; open POs commit their full value.
* The Pronto GL report holds no payment dates, so supplier payments in the cash view are modelled from payment terms (Settings).
* Risk tags are keyed on a stable row key, so they survive replacing the Pronto transactions with a newer export.
* Forecast days count from the day after the status date; earlier days belong to timesheets and accruals.
* Sharing: see `app/sync.py` for the journal format and merge rules, and `HANDOFF.md` for the design decisions.
* Native `.mpp` files are read with MPXJ, which needs Java installed (https://adoptium.net) and the `mpxj` and `JPype1` packages from requirements.txt. Without Java the upload says so; save the schedule as XML from MS Project or export the task list to Excel instead.

## Tests

```
.venv/bin/python -m pytest tests -q
```

The suite covers the engine and forecast methods, EAC and accrual handling, the Pronto tie-out and re-import, the allowance ledger and
initialisation lock, variations, templates, clone and wipe, the project schedule import, claim approval flowing into cost control, snapshot
comparison, the three revenue against cost views, and the risk release rules.

**Project setup steps (21/10 .52).** Every step has Back, Save and Next. Next or Back with unsaved changes asks whether to save first. Contract value, CBS and allowances and Project schedule each have their own Excel template (blank or current data) and Load from Excel; the header keeps the full template. The Project schedule step takes an internal schedule (drives dates) and an upstream schedule (client or head contract, reference only) by drag and drop. The Project schedule page now sits under Forecast.

**CMT upload (21/10 .53).** Cost control and Project setup have Load a CMT. It reads the CMT's Project Summary and Forecast Costs & Revenue sheets, shows a gap analysis (category totals reported only; forecast differences per line; CMT lines the app lacks; app lines the CMT lacks) and, per item, the user rejects or aligns. Aligning sets the line to MANUAL and loads the CMT forecast months from the status month on; a CMT line the app lacks becomes a new CBS line under its category. Undo this alignment is offered afterwards. Lines are matched by resource code, PO number, then by name, so check each match. Budgets, actuals and revenue are not changed by it.

**Menus (.53).** SETUP lists the setup steps (Project, Contract value, CBS and allowances, Project schedule, Pronto data, Initialise) plus Linked projects. COMMUNICATION: Stakeholders, Communication matrix, Meetings, Project org chart. PMO: Project library, Project lifecycle, Project gate, Project phase, Archive. Month-end review has a tile for logging project complexity and client behaviour.

**Wrong-project guard on Pronto uploads (.54).** Before a Pronto file is loaded, its project codes are compared with this project's Pronto project setting (else its number or code) and with the other projects. If it looks like another project's file, or does not match this project's Pronto project, the user is asked to confirm before loading.

**Project library and Lifecycle (.55).** PMO > Project library holds all knowledge documents: EPEC's gate papers and review checklists plus anything uploaded (any file to 15 MB, stored in the database as base64 so it travels with it), tagged by type, delivery phase and gate. PMO > Project lifecycle has tiles for Project gate, Project phase and Project library, and lists the library documents tagged for the open project's current phase and its latest and next gate. Project gate and Project phase open from those tiles. Back (top left) and Forward (top right) step through visited pages. Month-end review shows Landed (actual + accrual) on the left and Planned (previous forecast) on the right.

**Menu order (.56).** The groups in the left pane (OVERVIEW, PMO, SETUP and so on) can be dragged up or down by their heading; the order is kept on that PC (browser storage, key navOrder), not shared.

**Stakeholders, two places (.57).** OVERVIEW > Stakeholders is the company-wide directory (clients, employees, companies). COMMUNICATION > Stakeholders is this project's own register (name, organisation, role, contact, interest, influence, notes), which can be started from the org chart parties and the named project people. Default menu order: Overview, Setup, PMO, Communication, Revenue, Cost, Forecast, Reporting, Close-out, Control (still draggable).

**Project schedule page (.58).** FORECAST > Project schedule now shows the schedule as loaded (internal first, Client schedule one click away) with a timeline, key dates and a button to download the file as uploaded (MS Project, Excel or PDF; kept in the database). The upload, task linking and applying dates to the claim schedule and cost forecast moved behind the Update tile (`#/programme?view=update`). Schedules loaded before this release have no stored file until uploaded again.

**Setup drafts (.59).** On Project setup, a change on Contract value, CBS and allowances or Project schedule is a draft: the first change takes a restore point, Save keeps it, and leaving the step (menu, Next, Back, another project) asks Save / Don't save / Stay. Don't save puts the step back as it was; closing the tab with unsaved setup changes also warns. Everywhere else in the app a change saves at once, and the Setup page says so. Back, Save and Next appear above and below each step. Back and Forward in the top bar grey out when there is nowhere to go. The Pronto data page has a field for the project's Pronto code, which the wrong-project guard uses.
